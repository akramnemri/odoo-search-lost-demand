## Design choices

- **One Compose stack** for development, CI and the demo (ADR-003). CI runs the real `compose.yaml` instead of separate
  service containers, so it checks the same Elasticsearch users and roles as the laptop (decision 2026-11-14).
- **Pinned, reproducible images**: dated Odoo tag `19.0-20261015`, Elasticsearch/Kibana `9.5.5`; the Elasticsearch
  client added to the Odoo image is hash-locked (two SonarCloud findings on PR #8). Free Basic license only, asserted by
  `es-setup` and the doctor.
- **No secrets in the repository**: `odoo.conf` is a template filled from `.env` at container start; PostgreSQL
  credentials reach Odoo through `PG*` variables, never on a command line.
- **No `db_name` in `odoo.conf`**: with it, Odoo 19 creates a blank database at every start
  (`odoo/cli/server.py::main`). The database is created only by `shop db create`.
- **Tools talk to Odoo over JSON-2** (`/json/2/<model>/<method>`): XML-RPC and JSON-RPC are deprecated in Odoo 19.
- **The shop never waits on Elasticsearch** (ADR-006): every call runs in a 4-thread pool with a hard deadline
  (`EsClient._within`), because the client's own timeout does not cover a DNS lookup (8 s when the container is
  stopped). The Settings status is computed, never stored, and cached for 10 s.
- **Debugging in Docker** (ADR-014): the PyCharm configurations load the module from `/opt/project/addons`, the
  repository mount PyCharm maps itself, and disable Odoo's request time limit while paused.
- **Quality gate**: lint, tools tests (Ubuntu + Windows), compose validation and the module job are required on
  `develop` and `main`; SonarCloud runs on every PR.

## Problems met (and what fixed them)

| Problem | Cause | Fix |
|---|---|---|
| A blank database with login admin/admin appeared at every start | `db_name` in `odoo.conf` makes Odoo 19 create it | `db_name` removed; `dbfilter` keeps Odoo on `shop` |
| `shop db reset` swallowed its confirmation | `docker compose exec` forwards stdin | every Docker call without input uses `stdin=DEVNULL` |
| A new module was missing from Apps | Odoo 19 caches "manifest not found" per process | restart Odoo before Apps › Update Apps List |
| Settings took 7.7 s with Elasticsearch stopped | DNS lookup of a stopped container times out after 8 s; the client timeout does not cover it | thread pool with a hard deadline: 2.09 s |
| The integration user could not create products | in 19.0 only `product.group_product_manager` may, and only Settings implies it | group added; `shop db create` checks the right over JSON-2 |
| PyCharm never stopped at the breakpoint | PyCharm maps only the repository to `/opt/project`; the module ran from `/mnt/extra-addons` | `--addons-path=/opt/project/addons` in the debug configurations |
| A paused request could restart Odoo | threaded Odoo reloads when a request exceeds `limit_time_real` (120 s) | `--limit-time-real=0` while debugging |
| Step into Odoo core skipped | PyCharm turned on "debug just my code" | set off in `.run/`; PyCharm can rewrite `.run/` files, check `git diff .run` |
| `shop test module` said Odoo was down while it was healthy | PyCharm's exited `docker compose run` helpers share the service name | `parse_ps` skips one-off containers (#18) |
| First CI run: `shop up` reported the Odoo base image missing | BuildKit builds from the base image without tagging it locally | the job pulls the base image by name, read from the Dockerfile |
| SonarCloud S8541/S8544 on the new CI jobs | `uv` calls without `--no-build` / lock flag | every `uv` call in CI uses `--locked --no-build` |
| Free disk fell to 2.2 GB (2026-11-14) | outside the project (Docker images of other projects, other files) | freed by the supervisor; 72 GB free at the regression check |
